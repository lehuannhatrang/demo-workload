## Root cause hypothesis

The single most likely root cause is that the **`payments-api` container is intentionally configured to allocate 50MB of memory using the `stress` tool (`--vm-bytes 50M`), which consumes nearly the entirety of its 64MiB memory limit**, leaving insufficient headroom for container overhead and risking OOM termination.

**Concrete evidence:**
- The deployment's container arguments include `--vm-bytes 50M`, explicitly reserving 50MB of memory.
- The pod's memory limit is set to `64Mi` (≈67MB), leaving only ~7MB of headroom.
- The pod is running with **0 restarts**, indicating stable operation without crashes or OOMKills.
- There are **no errors in events** (e.g., image pull failures, scheduling issues, or evictions), confirming the high memory usage is workload-driven, not pathological.
- Resource usage of ~85% of 64MiB (~54.4MiB) aligns with 50MB allocation plus process/container overhead.

This is not a memory leak or unintended behavior, but a **configuration mismatch**: a synthetic memory load close to a tight limit triggers the alert.
