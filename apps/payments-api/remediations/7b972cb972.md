## Root cause hypothesis

The single most likely root cause is: **The `payments-api` container is intentionally configured to consume approximately 50MB of memory using the `--vm-bytes 50M` argument to the `stress` tool, which exceeds 75% of its 64Mi memory limit due to monitoring granularity and minor overhead fluctuations.**

This configuration causes sustained memory usage (~74.5% of 64Mi) that frequently crosses the 75% threshold used by the alerting rule, triggering the `HighPodMemory` alert. The pod remains within its hard limit (no OOM kill), confirming the behavior is within bounds but still sufficient to activate the alert. The alert is therefore valid and expected given the current resource limits and workload configuration.
